# OctoPrint integration

enderslicercura can connect directly to an existing OctoPrint server after slicing. OctoPrint remains the printer host; the Android app acts as an authenticated client and sends the already validated G-code generated by the bundled CuraEngine.

## Included functionality

### Setup and authentication

- Manual server URL or IP address, including OctoPrint installations mounted below a path prefix.
- OctoPrint Application Keys authorization with automatic polling after the user approves the request in the OctoPrint web interface.
- Manual user API-key fallback for servers where Application Keys are unavailable.
- API keys encrypted with an app-specific AES-GCM key held by Android Keystore.
- Connection test, server/API version, user, administrator flag and permission reporting.
- Configurable idle status refresh interval.
- HTTP support for normal trusted-LAN installations and HTTPS support for reverse proxies or remote access.

Do not place HTTP Basic Auth credentials inside the configured URL. When a reverse proxy requires additional authentication, configure a dedicated HTTPS endpoint that the Android device can access without embedding a password in the URL.

## Slice upload

The current validated `.gcode` file can be:

- uploaded only;
- uploaded and selected;
- uploaded, selected and started.

Uploads use fixed-length multipart transfer because OctoPrint requires a known content length. The UI reports byte progress and preserves the existing local G-code file if the transfer fails. Remote folder paths are supported.

Starting a print is intentionally separate from ordinary export. Confirm the printer is clear, the bed is prepared, the correct filament is loaded and the first layer can be supervised.

## Live status and job control

The OctoPrint panel reports:

- printer and serial connection state;
- nozzle, bed and chamber actual/target temperatures;
- selected file, completion, elapsed time, remaining time and current Z when available;
- pause, resume, start, restart and cancel controls;
- webcam snapshots, including OctoPrint flip and rotation settings.

The app polls more frequently while a print is active or paused. Polling failures leave the last known state visible and report the connection error.

## File manager

The file page recursively lists OctoPrint local storage and supports:

- refresh and filtering;
- selecting or starting a G-code file;
- deletion;
- folder creation;
- copy and move operations;
- file size, estimated print time and available-space reporting when provided by OctoPrint.

## Printer control

The control page supports:

- connecting and disconnecting the OctoPrint serial printer;
- port, baud rate and printer-profile selection;
- saved and automatic connection settings;
- relative X/Y/Z jogging at 0.1, 1 and 10 mm;
- individual-axis and all-axis homing;
- nozzle and bed targets, including heater-off actions;
- extrusion and retraction;
- live feed-rate and flow-rate overrides;
- one-line raw G-code commands.

Raw commands and motion/heater controls can damage a printer or create a fire risk when used incorrectly. The app validates basic ranges, but it cannot determine whether an otherwise valid command is safe for the connected machine.

## Webcam behavior

The app reads the snapshot URL and orientation settings from OctoPrint. A manual snapshot URL override is available for reverse proxies or webcam plugins that do not expose a usable URL through `/api/settings`.

Only bounded still images are fetched. The app does not keep an MJPEG stream open in the background; snapshot polling begins while the OctoPrint panel is visible and stops when it is closed.

## OctoPrint 1.8.3+/2.0 CSRF protection

Since 1.8.3 (and enforced as `devel.enableCsrfProtection` in 2.0), OctoPrint
defends non-GET API requests with a double-submit CSRF token. When the
protection is active on a 2.0 server, API-key requests without an existing
login session are rejected with a `400 CSRF validation failed` unless they
carry both the `csrf_token_P<port>` cookie (the cookiename gains an
`_R<root>` suffix behind a path prefix) and an `X-CSRF-Token` header with the
same value. The client obtains the pair from the anonymous server root once
per session, attaches it to every same-origin state-changing request and
transparently refreshes and retries on a CSRF rejection, so configured
servers keep working whether or not the flag is enabled.

## Local HTTP security

Android normally blocks cleartext networking for modern target SDKs. This app explicitly permits it because many local OctoPrint installations are reachable only through `http://octopi.local` or a private IP address.

Plain HTTP does not encrypt the API key, printer commands or uploaded G-code. Use it only on a trusted local network. Prefer HTTPS through a properly configured reverse proxy for guest Wi-Fi, remote access or any network that is not fully trusted.

## API coverage

The implementation uses OctoPrint's documented REST endpoints for:

- version and passive user login;
- printer state and printer commands;
- jobs and job commands;
- serial connection management;
- local file storage;
- server settings/webcam data;
- the bundled Application Keys plugin.

The client keeps OctoPrint-specific code isolated under `octoprint/`; CuraEngine, G-code validation and ordinary file export remain independent.
